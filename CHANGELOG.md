## [Unreleased]

### Added
- MPI-3.0 core support: neighbor collectives, large-count (`_x`) datatype
  queries on 64-bit `MPI_Count`, dynamic windows (`Win_create_dynamic`/
  `attach`/`detach`), and `Comm_idup`, across the OpenMPI/MPICH/Intel-MPI/
  MS-MPI backends under the `UNIMPI_MPI_TARGET_VERSION>=3` gate, with an
  MPI-3.0 core integration test.
- MPI-3.0 RMA epoch-model semantic tests (`lock_all`/`lock` + `flush*` +
  `Win_sync` + window Info) and a matched-probe semantic test
  (`Mprobe`/`Improbe`/`Mrecv`/`Imrecv`).
- MPI_Status source/tag/error accessors: the MPI C standard (through 3.x)
  exposes no accessor for these, so UniMPI adds per-backend function pointers
  `unimpi.status_get_source/_tag/_error` under the standard MPI-4.0/5.0 names
  `MPI_Status_get_source/_tag/_error` (returning an error code and writing the
  field through an out parameter). Direct `status.MPI_SOURCE` reads are not
  layout-portable across backends; see docs/API.md.

## [0.1.0-alpha] - 2026-08-29

First public pre-release. UniMPI is a C99 runtime-dispatch layer for MPI that
lets an application load Open MPI, MPICH, Intel MPI, or Microsoft MPI at
runtime against a single stable interface.

### Coverage

- **MPI-2.2 base surface: 305 / 305 canonical entities exposed (100%).**
  - 293 vtable function-pointer fields (MPI function dispatch)
  - 12 predefined attribute callback values (extern globals populated per-backend
    at init: `MPI_COMM_DUP_FN`, `MPI_TYPE_NULL_COPY_FN`, etc.)
- **MPI-3.0+ surface: 41 additional fields** gated behind
  `UNIMPI_MPI_AT_LEAST(3,0)` and available when the user builds with
  `-DUNIMPI_MPI_TARGET_VERSION=3`.
- 311 direct `MPI_*` standard-name aliases in `unimpi_std_macros.h`.

### Backends

- Open MPI (Linux / macOS)
- MPICH (Linux / macOS)
- Intel MPI (Linux)
- MS-MPI (Windows)

Each backend is loaded at runtime via `dlopen` / `dlsym` (POSIX) or
`LoadLibrary` / `GetProcAddress` (Windows). Auto-detection selects the first
available backend; manual selection via `UNIMPI_BACKEND` or `UNIMPI_LIBRARY`
environment variables overrides it.

### API surface

- **Dual API style:** vtable dispatch (`unimpi.send(...)`) and optional
  standard-name macros (`MPI_Send(...)` via `#define UNIMPI_USE_STD_NAMES`).
- **Zero-overhead design:** single function-pointer indirection per call
  (no wrapper layers, no allocations on the hot path).
- **Full MPI category coverage:** point-to-point, collectives, datatypes, RMA,
  parallel I/O, dynamic processes, error handling, topologies (cart/graph/
  distributed), attributes, Fortran conversions, generalized requests,
  datarep registration, and more.

### Build system

- CMake 3.10+, C99.
- **Compile-time MPI target version:** default is MPI-2.2 (the guaranteed base
  surface); users targeting MPI-3.x pass
  `-DUNIMPI_MPI_TARGET_VERSION=3 -DUNIMPI_MPI_TARGET_SUBVERSION=<x>` to enable
  MPI-3.0+ fields in the vtable.
- `cmake -S . -B build` / `cmake --build build` / `ctest --test-dir build`.
- Tests split into: unit tests (no MPI runtime), real-backend tests
  (opt-in via `-DUNIMPI_BUILD_MPI_TESTS=ON`, requires `mpirun`/`mpiexec`).

### Library versioning

- `unimpi_version.h` (generated by CMake from `unimpi_version.h.in`) exposes:
  - `UNIMPI_VERSION_MAJOR` / `MINOR` / `PATCH` / `PRERELEASE` / `STRING`
  - `UNIMPI_VERSION_NUMERICAL` (`0xMMNNPPPP`) for compile-time gating
  - `unimpi_get_version()` runtime query (returns `UNIMPI_VERSION_STRING`)
- Single source of truth is `CMakeLists.txt` (`project(VERSION ...)` +
  `UNIMPI_VERSION_PRERELEASE`).

### Tools

- `tools/mpi_version_gate.py`:
  - `check`: mechanical audit of MPI-version gating across vtable, std macros,
    and all 4 backends (6 clusters / 41 gated entities).
  - `base`: verifies every MPI-2.2 canonical entity is present in the
    always-present surface (305/305 expected).

### Known limitations

- MPI-3.0+ and MPI-4.0 fields are not in the default 2.2 surface; opt in via
  the target-version CMake flags.
- User datarep registration (`MPI_Register_datarep`) is bound but returns
  `MPI_ERR_OTHER` on Open MPI and MPICH (the backends themselves do not
  implement it); the test asserts a valid dispatch rather than unconditional
  success.
- Predefined attribute callbacks are backend-specific compile-time values
  (`OMPI_C_MPI_*_FN` on Open MPI, shared `MPIR_Dup_fn` on MPICH-family),
  exposed as extern globals rather than vtable fields.
